## 1. Stale foundation test: `schema.test.ts > packet discovery`

**What:** `tests/schema.test.ts:20-23` hard-codes the full packet set:

```ts
it('finds the three wave-1 packets', () => {
  const ids = packets.map((p) => p.id).sort();
  expect(ids).toEqual(['w1-l1', 'w2-l3', 'w4-l4']);
});
```

**Why it fails now:** every wave-2 author drops new packets into the shared
`content/levels/` tree, so the discovered set is no longer the three wave-1
ids. This assertion fails for ALL authors simultaneously, independent of any
single author's files.

**Which level:** none specifically — it is a foundation/scaffolding test, not
an author-owned file. I did not edit it (not in my ownership per the brief).

**Proposed minimal change (lead):** replace the exact-set assertion with a
superset + per-packet invariant check, e.g.

```ts
it('discovers packets and every file stem matches its id', () => {
  expect(packets.length).toBeGreaterThanOrEqual(3);
  // stem==id is already enforced in loadAllPackets()
  expect(new Set(packets.map((p) => p.id)).size).toBe(packets.length); // unique ids
});
```

## 2. Stale foundation test: `progress.test.ts > isLevelUnlocked > later level locked until the prior one is passed`

**What:** `tests/progress.test.ts:66-73` asserts that `w2-l3` is locked until
`w1-l1` is passed:

```ts
const w2 = packets.find((p) => p.id === 'w2-l3')!;
expect(isLevelUnlocked(w2, packets, prog)).toBe(false);
const after = recordPass(prog, w1, 2, 35);          // pass w1-l1
expect(isLevelUnlocked(w2, packets, after)).toBe(true);
```

**Why it fails now:** this relied on the 3-packet tree where `w1-l1` was the
immediate predecessor of `w2-l3`. With the W1 and W2 authors' new packets
(`w1-l2`, `w1-l3`, `w2-l1`, `w2-l2`) now present, the predecessor of `w2-l3` is
no longer `w1-l1`, so passing only `w1-l1` does not unlock `w2-l3`. This is
caused by the W1/W2 authors' files, not World 3 — my packets sort at the end of
their world and cannot affect whether `w2-l3` unlocks.

**Which level:** none of mine. Foundation test.

**Proposed minimal change (lead):** rewrite the unlock test against adjacent
packets resolved from the loaded order rather than hard-coded ids, e.g. take
`packets[0]` and `packets[1]` and assert `packets[1]` unlocks only after
`packets[0]` passes. That stays correct as the tree grows.
