# Wave-2 request — World 2 (Spot the Guess)

Author: World 2 level author (w2-l1, w2-l2, w2-l4, w2-boss)

## 1. Count-based "at most N" pass conditions aren't expressible

**What.** The schema's `RuleConditions` (`requireAll` / `requireAny` / `forbidAny`) and the
`expectPass` oracle can express "all of", "at least one of", and "none of" a set — but not
"at most K of a set" or "exactly K of a set" where K > 0.

**Why it matters.** The curriculum (§3) specifies two levels whose *intended* grader is
count-tolerant:

- **W2 L2 "Highlight the guess":** pass = tagged the **3 computed** claims AND tagged
  **≤ 1 of the 4 safe** claims. The "≤1 safe" tolerance (one accidental over-tag is
  forgiven) cannot be stated in `expectPass`, and because the combination test asserts
  `engine.isPass === expectedToPass(...)` across all 2^n combinations, even a simulator
  couldn't carry it — the oracle itself can't count.

**Which level / what I shipped.** `content/levels/w2-l2.json`. I authored the pass as the
expressible, strictly-two-sided version: **all 3 computed tagged AND zero safe tagged**
(`requireAll` the 3 computed, `forbidAny` the 4 safe). This is *stricter* than the
curriculum's "≤1 safe" — it forgives no over-tag — but it preserves the lesson (catches both
misses and over-tagging) and keeps the gate green. The feedback copy still teaches "aim at
the computed claims," matching the curriculum's over-tag feedback.

**Proposed minimal change (Phase 2).** Add an optional count clause to `RuleConditions` and
to `ExpectPass`, e.g.:

```ts
interface RuleConditions {
  // ...existing
  atMost?: { ids: string[]; n: number };   // at most n of these ids may be on
  atLeast?: { ids: string[]; n: number };  // at least n of these ids must be on
}
```

`conditionsMatch` and `expectedToPass` both honor it (both already live in
`src/engine/engine.ts`, so the oracle stays independent of the rule table). Then W2 L2's
`expectPass` becomes `requireAll: [3 computed]` + `atMost: { ids: [4 safe], n: 1 }`, matching
the curriculum exactly.

**Not blocking.** The strict version is a correct, shippable formative rung today; this is a
fidelity gap against the curriculum's tolerance, not a broken level.

## Resolved by lead (2026-10-11)
Added optional `atMost` / `atLeast` count clauses to `RuleConditions` (engine `conditionsMatch`, used by both rules and the `expectPass` oracle). `w2-l2` now matches the curriculum: all 3 computed tagged and at most 1 safe tag.
